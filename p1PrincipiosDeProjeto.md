#Divisão de pedaços - melhorar resolução de problemas
-> decomposição por partes
    -> Formas independetes, abstratas
    -> Prioridades:
        -`Integridade conceitual`
            ->Usuario:
            O usuario sabe usar de forma funcional
            ->Desenvolvedor:
            Como a solução é contruida
                EX: padronização de medidas em tabelas(usuario)
                Uso de framework uso do mesmo n altera a aplicação
        -`Ocultaçamento de Informação`
            ->Deixar publico apenas o q deve usar, ou para poder alterar toda estrutura interna,
                **Rever
        -`Coesão`
            ->Uma classe deve ter uma única responsabilidade/motivo unico objetivo/interesse
            ->Todos os métodos relacionados aquel interesse
            ->Diminiu a complexiadade da classe
        -`Acoplamento`
            ->A força de conexão entre duas classes
            ->Grau de dependencia quanto elas dependem da outra
            ->Quanto menos ou de forma correta melhorar
                ->Aceitavel:
                    ->Natural, não tem dependencia muito forte q pode gerar problema no código
                    ->Classe A para classe B
                ->Ruim:
                    ->Depende de algo exclusivo
                    ->Quando a mudança de B podem impactar A

    DEpois revisão dos principios **Solid**
